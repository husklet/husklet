# Workspace extension protocol specification

`v1.json` is generated from the authoritative Rust wire enums by:

```sh
HL_EXTENSION_SPEC_GENERATE=1 cargo run -p hl-extension --bin hl-extension-spec -- --write
```

Consumers must require `specification_version == 1` and select the document
whose `protocol_version` they implement. `roots` contains complete schemas for
`request`, `reply`, and `failure`; every local `ref` resolves through
`definitions`. Together they represent field wire names, enum variants,
optionals, sequences, maps, tuples and exact integer widths. Requests and
replies retain their actual adjacent JSON tags (`call`/`reply`) and content key
(`with`) in each root's `serde` object.

The graph is closed: `Frame`, `SourceMutation`, and all of their `hl-gui` wire
types are included in `definitions`, and no `external_ref` is permitted. Rust
newtype structs and one-field enum variants use `kind: "newtype"` with their
wire value in `of`; they are not JSON objects or one-element arrays.
Capabilities and topics carry exact wire spellings, and topic entries include
their required capability. Framing integer endianness, channel parity, kind
codes, flags, and hard payload limit are normative.

The crate test compares generated bytes with the checked-in file. Changes to a
request, reply, failure, or transitively referenced model stale the artifact;
an unresolved referenced model fails generation rather than emitting a partial
schema.

Normal Cargo builds also verify the source fingerprint embedded in `v1.json`
and the whole-document fingerprint in `v1.fnv1a64`. The build script never
writes either file. The explicit environment variable above bypasses only that
pre-build stale check so the generator can repair an out-of-date pair; the
compiled generator still derives both artifacts from the authoritative Rust.
