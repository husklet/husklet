# Render-stack deep audit — wave K: generated shim surfaces

Audit date: 2026-07-12. Documentation only.

## Non-negotiable compatibility rule

Generated `gl*`, `egl*`, `vk*`, `cu*`, `cuda*`, and `__cuda*` exports are loader/dynamic-linker ABI. Rust call graphs do not describe their consumers. Do not remove an exported symbol unless the advertised API/profile, loader proc-address rules, old-image compatibility, and real guest resolution traces all prove it unreachable. Returning a truthful failure is preferable to removing a symbol that a loader expects to resolve.

Audited generators:

- `dd-shim-gl/build.rs` + `registry/gles2_egl.manifest`
- `dd-shim-vk/build.rs` + `vk_commands.manifest` + `vk_command_origins.manifest`
- `dd-shim-cuda/build.rs` + `cuda_driver.manifest`
- `dd-shim-cudart/build.rs` + `cudart.manifest`

## Immediate safe internal simplifications

### Unused generated GL metadata

`ADVERTISED_GLSL_VERSION_STR` and `ADVERTISED_GL_EXTENSIONS_STR` are emitted by `dd-shim-gl/build.rs` but have no repository consumer outside their generated definitions. Runtime queries use NUL-terminated byte constants/list/count; tests use the version string, major/minor, list, and count.

Safe deletion set:

1. Stop emitting the two unused Rust `&str` aliases.
2. Keep `ADVERTISED_GLSL_VERSION`, `ADVERTISED_GL_EXTENSIONS`, `ADVERTISED_GL_EXTENSIONS_LIST`, count, version bytes, and major/minor.
3. Run GL unit/integration tests and guest `glGetString`/`glGetStringi` probes.

Effect is Rust metadata/text reduction only; exported C ABI and query bytes remain unchanged. Because these are public Rust constants, confirm no out-of-workspace Rust tooling imports them before removal.

### Shared generator type/signature helpers

All four build scripts independently implement C-type parsing, pointer constness, scalar mapping, default return selection, Rust keyword escaping, parameter naming, manifest validation, and `#[no_mangle]` function emission. Differences are mostly policy inputs, not parser semantics.

Extract a build-only shared helper (for example `build-support/shim_registry.rs`, included by path) with golden generated-output tests. Keep per-API policy in each generator. This reduces maintenance and fixes pointer/keyword bugs once without changing generated bytes. Validate by hashing generated Rust before/after for every guest architecture and comparing exported symbols with `readelf -Ws`/`nm`.

Confidence: high if generated outputs are byte-equivalent. Runtime/off-state effect: none.

### Remove stale generator prose

CUDA/CUDART comments still describe a “generated long tail” and default stubs even where `GENERATED_STUBS == 0` is enforced. Update comments to say the generator is fail-safe for future manifest additions while the current surface is fully hand-implemented. This avoids maintenance confusion; no code effect.

## Duplicate sources of truth

### Hand-maintained implementation/classification tables

Each manifest declares names/signatures, while build scripts separately maintain `IMPLEMENTED`; GL also maintains `PARTIAL`, `ES3_FULL`, and `SENTINEL_RETURN`; CUDA/CUDART use separate `capability(name)` matches; Vulkan uses `partial_note` plus an origin sidecar. Count tests catch totals but can miss a same-count name swap or stale note.

Preferred migration:

- Add a reviewed classification sidecar keyed by symbol (`full|partial|unsupported`, error, profile/origin, note), or extend committed manifests with those fields.
- Generate implementation sets, capability inventory, sentinel behavior, and census from that one record.
- Fail build on missing/duplicate/unknown classification.
- Retain a source-body/export check proving every `full` symbol has exactly one hand-written definition and every generated symbol has exactly one stub.

Do not derive “implemented” by fragile Rust source text inspection. A committed machine-readable classification is the review boundary.

### Vulkan advertised extensions

`dd-shim-vk/build.rs::advertised_extensions` duplicates `src/capability.rs::{ADVERTISED_INSTANCE_EXTENSIONS, ADVERTISED_DEVICE_EXTENSIONS}`. Drift changes stub error selection (`EXTENSION_NOT_PRESENT` versus `FEATURE_NOT_PRESENT`) without changing runtime enumeration.

Safe consolidation: store advertised extensions in one build-readable manifest and generate the runtime constants plus stub policy from it. Validate exact instance/device enumeration and every extension-origin stub error.

### Error/version constants

Build scripts copy Vulkan/CUDA numeric errors from runtime `types.rs`/`result.rs`; tests cross-check some values. Generate a tiny shared constants module from one committed ABI table, or make build scripts parse an API-specific constants sidecar. Preserve numeric output and C ABI. This is maintenance-only.

## Generated metadata and product off-state cost

`CAPABILITIES` embeds one record per exported symbol, including names and explanatory notes. Repository consumers are census/truthfulness tests; production stubs return their preselected errors directly and do not query the inventory. Count constants are likewise primarily tests/docs.

Candidate product-size reduction:

1. Keep minimal compile-time counts required by product code.
2. Gate full names/notes inventory behind `cfg(test)` or a new `capability-inventory` Cargo feature used by audit tools.
3. Ensure integration tests that compile the library without `cfg(test)` enable the feature explicitly.
4. Compare guest `.so` size/rodata and verify identical exported symbol table and runtime behavior.

Risk: public Rust metadata API changes; C ABI unchanged. Confidence: medium until out-of-workspace audit tooling is checked. Runtime speed effect is negligible; load/page footprint may improve.

`DISPATCH_NAMES` in Vulkan is not purely redundant today: tests use it to prove every proc-address name resolves and capability records match. `dispatch_addr` is runtime loader behavior. If inventory is gated, keep a generated dispatch table or equivalent runtime resolver.

## Exported but outside truthful advertised profiles

### Vulkan

The ICD advertises Vulkan 1.0 plus four extensions, while the manifest/export table includes the broad vk.xml surface. `vkGetInstanceProcAddr`/`vkGetDeviceProcAddr` currently resolve the whole generated table permissively, including newer-core and unadvertised-extension commands, whose stubs then fail truthfully.

Do **not** remove symbols. First correct proc-address visibility according to loader rules, instance/device scope, enabled extension, and advertised core version. Keep hidden symbols exported for loader/old-image compatibility if necessary, but return NULL when the API contract requires it. Add loader-driven tests for NULL/non-NULL resolution across 1.0, unadvertised extensions, and enabled swapchain/surface commands.

This is a behavioral correctness task, not dead-code cleanup.

### GLES/EGL

The coherent default is GLES 2.0, yet ES3 symbols exist because `DD_SHIM_ES3` explicitly enables tests/guests and loaders may resolve symbols independently of context version. Keep exports. Classify mandatory ES2 functions separately from optional/ES3 functions so completeness prose cannot imply every exported symbol is advertised core.

### CUDA/CUDART

CUDA has no Vulkan-like per-context proc-address filtering for ordinary dynamic linking; applications and runtimes resolve broad symbols from the soname. Unsupported functions must remain exported and return defined CUDA errors. Removal requires a real driver/runtime version compatibility policy and guest loader traces.

## Build-time features and no-op configuration

The five shim Cargo manifests declare no `[features]`; repository search finds no `cfg(feature=...)` or `CARGO_FEATURE_*` branch in shim sources/build scripts. Therefore there is no current no-op Cargo feature to delete.

Crate types are intentional:

- `cdylib` is deployed ABI.
- `rlib` supports Rust tests and cross-crate validation.
- `dd-shim-common` is `rlib` only and statically links into shims.

Do not remove `rlib` without migrating tests; it affects build artifacts, not runtime `.so` behavior.

## Registry/extraction maintenance

- Extraction scripts and committed manifests should record upstream revision/hash and deterministic command. Keep them; they are regeneration provenance, not product code.
- Validate manifests are sorted, unique, and signature-stable in build scripts.
- Add a generated-output snapshot hash only as a review aid, not as a substitute for behavioral ABI tests.
- Ensure `cargo:rerun-if-changed` covers every classification/origin/advertisement sidecar introduced by consolidation.

## Comments/classification findings

- “Full” means complete only for the modeled domain; notes must identify bounded behavior. Avoid comments equating a hand-written body with full semantics.
- CUDA/CUDART default-to-`Full` classification is risky: a newly added manifest name silently becomes full unless separately listed. Default should be fail-closed/unclassified, requiring explicit review.
- Vulkan absent origin defaults to unadvertised extension, which is conservative; keep fail-closed behavior.
- GL names absent from `IMPLEMENTED`/`PARTIAL` become truthful stubs, also fail-closed. Preserve this safer default.

## Validation matrix for generator changes

1. Build both guest architectures.
2. Compare `readelf -Ws` exported names, binding, type, and soname.
3. Run loader journeys: EGL/GLES queries, Vulkan loader negotiation/proc-address, CUDA driver/runtime dynamic linking.
4. Run capability census and sentinel-output tests.
5. Compare generated source hashes when the intended change is internal-only.
6. Verify unsupported calls return the same defined errors and sanitize output pointers identically.
7. Measure `.text`/`.rodata` before and after inventory gating.

## Safe sequence

1. Remove the two unused GL Rust string aliases after external-tool check.
2. Extract byte-equivalent shared generator helpers.
3. Consolidate advertised-extension/error constants into build-readable sources.
4. Move classifications to explicit fail-closed manifests.
5. Feature-gate full capability notes/names only after tooling migration.
6. Fix proc-address visibility without deleting exported ABI symbols.

This sequence reduces duplication and product metadata while preserving loader/profile compatibility.
