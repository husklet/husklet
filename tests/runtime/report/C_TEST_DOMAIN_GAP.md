# Retained C test-domain parity audit

Generated by static inspection of the live retained C tree and the Rust worktree. This report deliberately excludes `tests/compat/**`: guest compatibility rows are already normalized in `C_INVENTORY_GAP.tsv`.

## Scope and counting

The unit denominator is one configured C source domain, not one assertion or one invocation. `hl_unit()` registers one CTest process per source; debug builds and Linux/macOS linkage variants remain variants of that source domain. Parameterized integration runners are one umbrella row with their parameter axes recorded in `c_function_evidence`, so their cases are neither flattened nor double-counted.

Classification is behavioral:

- `mapped`: Rust tests directly cover the named C contract.
- `partial`: Rust evidence covers part of the contract or a lower/upper boundary, but not the complete C source domain.
- `missing`: no Rust crate test was found for the C contract.

## Exact result

| Scope | Total | Mapped | Partial | Missing |
|---|---:|---:|---:|---:|
| Configured C unit source domains | 118 | 31 | 54 | 33 |
| C integration/parameterized umbrellas | 19 | 0 | 8 | 11 |
| Combined | 137 | 31 | 62 | 44 |

The TSV is the authoritative row-level evidence. C function evidence is drawn from test entry functions or the first called `hl_*` APIs; registration evidence points to the live CMake logic, not generated build files.

`guest_fetch` is partial after the executable-span migration. Rust now covers
execute permission, page/mapping traversal, bounded atomic staging, production
arena wiring, and live backing reads. Exact retained regressions for patterned
15-byte page crossing, file-backed rewrite visibility, surviving-prefix fetch
after unmap, and publication into a prior hole remain; the C-only direct-host
fallback mechanism is not part of Rust's arena-owned address model. The
assertion-level mapping is recorded in `MIGRATION_HANDOFF.md`.

`eventfd_fork` is mapped through the production descriptor/event fork path.
Focused warning-strict tests prove the retained shared-OFD counter and status,
readiness-subscription lifetime, child/parent close ordering, and staged-fork
rollback behavior.

The checkpoint/memfd umbrella remains partial. Its first restored-backing phase
now makes the concrete memory host construct the replacement shared-object store
and backing registry; the runtime publishes that exact store, preserving the
single MAP_SHARED backing identity instead of snapshot-copying restored mappings.
RuntimeMemfd cursor/OFD payload, inert descriptor binding, registry publication,
SCM queue-only roots, and their rollback matrix now have source-level production
owners and focused Rust tests. The umbrella remains partial and no row or
aggregate count is promoted: serialized compilation/execution, multi-process
aggregate identity, ordinary File-family restore and retained C differentials
remain open.

## Priority order

1. **P0 native execution contracts:** pcache ABI, guest fetch/naked entry, native capacity, AArch64 emission, and the x86 lowerer families. Interpreter coverage is not counted as native lowering parity. The target-side memory projection gate is mapped through production generation, transition, cache invalidation, and fault-resolution paths.
2. **P1 host/platform and provider gaps:** affinity, eventfd fork, provider demux/files, persistence, xattr cache, macOS fork/DNS/destruction, staged package activation, dual-backend linkage, fuzz/performance, and CI/direct-launch harnesses.
3. **P2 partial semantic domains:** complete C edge matrices for checkpoint, sentry authority, host services, process/fork, provider lifecycle, signal frames, VFS resolution, and platform binding umbrellas.

## Registration observations

- `cmake/Phase3Units.cmake` owns the generic `hl_unit` registration and explicit source/link overrides. Linux/macOS variants do not create new behavioral domains.
- `cmake/Phase3Gates.cmake` registers lifecycle, production, checkpoint, performance, fuzz, nested, and cross-checkpoint umbrellas. Each umbrella remains a single row here with its parameterization stated.
- `cmake/Phase4Mac.cmake` adds macOS host-mechanism variants and Objective-C DNS/fork coverage.
- `cmake/PackageTest.cmake`, `tools/CMakeLists.txt`, and `linter/CMakeLists.txt` own package-consumer and repository-tool integration tests.
- Compatibility-manifest and soak guest cases are intentionally absent from this report.

## Caveat

This is a static parity audit, not a test execution report. “Mapped” means the Rust source contains direct crate-test evidence for the contract; it does not claim the C and Rust suites were run together or are byte-for-byte differential.
